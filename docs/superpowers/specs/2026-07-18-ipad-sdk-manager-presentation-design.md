# IPAd SDK 与 IPAd Manager 分层母版型演示稿设计

## 1. 目标

制作一套可按受众裁剪的中文技术母版演示稿，完整说明当前仓库中的 IPAd SDK 能力、公开接口、外部调用方式、IPAd Manager 分层实现、模块功能、兼容性、一键部署与使用方法。

演示稿必须以当前代码和仓库文档为事实依据，并显式区分：

- 已实现且已接入 Manager GUI；
- SDK 或 Wrapper 已实现，但尚未完整接入 GUI；
- 当前为占位实现或返回 `eNotImpl`；
- 仅属于设计建议或后续演进方向。

## 2. 受众与裁剪方式

母版同时服务三类受众：

1. 管理层：关注产品定位、业务价值、完成度、风险与路线图；
2. 客户及合作伙伴：关注功能范围、部署方式、兼容性、操作流程和集成边界；
3. 研发及技术评审：关注接口契约、分层、调用链、线程与内存、构建选项和技术债。

每页右下角使用轻量标签标记推荐受众：`管理`、`客户`、`研发`。目录页和结尾附带三套裁剪清单，使使用者能够通过隐藏章节快速生成不同版本。

## 3. 叙事结构

采用由浅入深的分层母版结构，预计 40–50 页：

### A. 定位与全景

- 封面；
- 阅读导航与三类裁剪路径；
- 一页执行摘要；
- 产品定位、边界与关键价值；
- IPAd SDK、IPAd Manager、eUICC、eIM、SM-DP+ 关系图；
- 典型业务场景与端到端业务流。

### B. SDK 能力与接口

- SDK 能力地图；
- 初始化、反初始化、事件回调和任务回调；
- eUICC 信息查询：EID、EuiccInfo1/2、证书/PKID、Profile、EIM 配置；
- Fallback、Rollback、应急 Profile；
- 通知读取、投递、单条投递、删除；
- MQTT、LwM2M、HTTP 服务；
- ES10、APDU、AT 驱动和 TLV 编解码调用链；
- API 分类矩阵、参数约束、返回码、资源释放规则；
- 外部应用接入步骤与最小调用示例；
- 典型调用时序和异常路径。

### C. IPAd Manager 实现

- Manager 总体分层架构；
- GTK GUI、业务逻辑、命令构造、SDK Wrapper、SDK Core、硬件与网络适配层职责；
- 主程序启动与关闭流程；
- GUI 命令分发与 Wrapper 调用链；
- 各功能模板/页面的职责和输入输出；
- 配置管理、日志、错误映射、线程与生命周期；
- 当前 GUI 接通矩阵；
- Wrapper 已封装但未完整接入矩阵；
- Profile 管理占位能力与文档偏差说明。

### D. 兼容性、部署与使用

- 操作系统与 WSL/Ubuntu 环境；
- 编译器、CMake、GTK、curl、MQTT、LwM2M 依赖；
- SGP.32、SGP.22、AT、PCSC 与协议构建选项；
- 兼容性矩阵与当前验证边界；
- `quickstart.sh`、`build_sdk.sh`、`build_all.sh` 的职责；
- 一键部署流程和目录产物；
- 安装、配置、编译、启动、连接设备和执行功能；
- 常见故障与排查树；
- 安全、证书与生产部署注意事项。

### E. 状态、风险与路线图

- 当前实现成熟度总览；
- 代码与发布说明不一致之处；
- 初始化异步状态、空事件回调、线程参数生命周期、Profile 内存释放、字符串分发等风险；
- 推荐的短、中、长期演进路线；
- 三类受众裁剪清单；
- 总结。

### F. 技术附录

- 完整公开 API 索引；
- Wrapper API 索引；
- 错误码；
- 配置项；
- CMake 构建选项；
- 术语表与代码导航。

## 4. 视觉与模板

严格复用用户指定的 Business Review PowerPoint 模板，不混入其他主题：

- 16:9；
- 白色或浅灰背景；
- 钴蓝为主强调色，黑灰作为正文和辅助信息；
- 大标题、清晰分隔线和充足留白；
- 架构、调用链、时序、部署和排障信息优先使用图形表达；
- 表格只用于精确映射和兼容性比较；
- 代码仅展示最小必要片段，完整签名放入附录；
- 不使用无证据的产品截图、性能数字或客户案例；
- 若模板和内容允许，仅使用抽象技术概念图作封面或章节过渡，不伪造产品界面。

## 5. 事实依据与标记规则

主要事实来源：

- `ipa_sdk_pc/include/ipa.h`、`ipa_core.h`、`typedefs.h`、`es10_typedefs.h`；
- `ipad_host_app/include/ipad_wrapper.h`；
- `ipad_host_app/src/sdk_wrapper/ipad_wrapper.c`；
- `ipad_host_app/src/gui/gui_main.c`；
- `ipad_host_app/include/app_api_definitions.h`；
- SDK/Manager CMake 文件和构建脚本；
- README、架构、API、用户和配置文档；
- 版本说明仅作为历史信息，并与当前实现交叉核对。

状态标记统一为：

- 蓝色实心：当前已实现并形成可用调用链；
- 蓝色描边：底层存在，Manager 接入不完整；
- 灰色：占位、未实现或未经验证；
- 橙色：风险、限制或需要生产化加固；
- 虚线：建议架构或路线图内容。

## 6. 质量标准

- 每页标题表达结论或明确主题；
- 任何能力陈述都能回溯到代码或仓库文档；
- 不把接口声明等同于可用实现；
- 不把 Wrapper 存在等同于 GUI 已接入；
- 不把历史发布说明中的“完成”直接视为当前事实；
- 所有架构图、调用链和矩阵使用一致术语；
- 每页通过渲染检查，无溢出、遮挡、截断和不可读文本；
- 最终文件保存在仓库 `outputs/` 下，并通过 PowerPoint 结构和模板一致性检查。

## 7. 最终交付

- 一份完整、可裁剪的 `.pptx` 母版演示稿；
- 文件内含三类受众裁剪建议；
- 完整技术细节集中到附录，正文保持可演示性；
- 交付前逐页渲染并检查版式和内容一致性。
